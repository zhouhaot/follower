## 优先整改（按影响排序）

### A1 · P1 · 手机详情的视觉阅读顺序与 DOM / 焦点顺序相反

**已确认结构缺陷。** public/flower-detail.mjs:186-231 把展台及展示切换放在简介之前；public/exhibition.css:250 使用 `.flower-intro{order:-1}` 将简介移到手机视觉顶部。实时可访问性树仍先遇到“作品 / 珠光光影 / 更多观看方式 / 观察提示”，之后才是 h1、收藏和解说。截图 screenshots/detail-390.png 则先显示标题、收藏、解说，再显示画作。这会使键盘用户先跳到屏幕较下方，再回到上方简介，标题也未在辅助技术阅读顺序中及时出现。

**整改：** 将简介置于 DOM 的展台之前；桌面用显式 grid-area 保留左画作右简介。手机自然顺序为标题简介 → 作品 → 展示控制 → 阅读/收藏/解说（可将标题块与操作块合理分开，但避免继续使用 order 制造第二套顺序）。至少让 DOM、视觉、Tab 主顺序一致，并保留 WebGL 容器尺寸。建议 `$impeccable adapt` / `harden`。

**验收：** 390 和 320 下 Tab 顺序单向随页面向下，h1 在展示控制前；桌面两栏视觉不变，作品完整。

### A2 · P2 · 手机首页的“当前作品”和主入口距离过远，切换区内部层级倒置

**视觉与可发现性判断，非功能失效。** public/app.mjs:19 的“开始观展”在展名旁，当前作品标题、上一张/下一张、五项选择位于画作之后（25-35）。public/exhibition.css:287-290 进一步把手机箭头排在“三维花朵”前，但 DOM 中三维链接在箭头前。final/home-390.png 和 home-320.png 显示：用户到下方选择另一张后，主按钮已在远处；最近可见的进入链接只强调三维，故事入口主要依赖点击图片。这让“选花 → 进入这朵花”的关系变弱。

**整改：** 将当前作品名称、序号、前后切换归为紧凑的一组；在同组提供明确“阅读这朵花”入口，保持与选中作品同步。展名旁入口可保留为首次开始。让 DOM 顺序匹配移动视觉顺序，不用 CSS 把三维链接和箭头对调。五项选择保留完整名称；无需新增轮播自动播放或额外动画。建议 `$impeccable layout` / `clarify`。

**验收：** 手机切换至任意作品后，在选择区域附近能直接进入该作品故事，链接、标题、图片同步；焦点顺序无上下来回。

### A3 · P2 · “看懂这幅设计”的标注有交互外观，但缺少标准按钮和选中语义

**已确认组件语义缺陷。** public/flower-detail.mjs:151-171 以 click 与 focus 改变 active；260-263 使用 `li tabindex="0"` 作为可点击文字项；257 的图片标注按钮没有 aria-pressed。当前 AX 树把侧边选项读为普通列表文字，无法获知正在显示哪项；每个标注又在图片和列表重复产生焦点。鼠标可用，不代表这个组件已经形成完整键盘模式。

**整改：** 使用一套命名明确的原生按钮作为主要选项，Enter/Space 激活；同步 aria-pressed 或采用完整的 tab 语义与关联面板。图片热区可继续保留，但同步选中状态，避免仅靠颜色判断。不要让单纯 Tab 经过项目就改变正文；选择由激活触发。建议 `$impeccable harden`。

**验收：** 每个标注可用键盘选择、当前项能被辅助技术辨识，正文状态随激活更新，焦点可见。

### A4 · P2 · 收藏状态视觉语法跨页面反转

**已确认样式差异，影响程度属于设计判断。** public/exhibition.css:103-104 的图录 `.collect-btn.collected` 为浅青绿实底；:132-133 的详情 `#collect-btn.collected` 则转为深底描边，未收藏反而是浅色实底。screenshots/catalogue-1440.png、detail-390.png 可见同一“已收藏”状态不同。花册取消又采用独立标签。文字仍正确，因此不是保存故障，但用户需重新理解状态与主操作的视觉关系。

**整改：** 统一“已收藏”的图标/文字/底色语义；例如未收藏描边加号、已收藏青绿实底加勾，详情重要入口通过位置与尺寸强调，勿靠反转状态色。所有界面同名操作保留一致反馈文字和可撤回说明。建议 `$impeccable polish`。

**验收：** 同一作品在图录、详情、花册间来回，选中状态识别不变；操作结果与实际本机状态一致。

### A5 · P2 · 备份页把常用动作、撤销和旧版工具放成同一级，初始状态出现空预检色块

**已确认布局结构，优先级属于设计判断。** public/backup-page.mjs:9-12 把“下载花册备份 JSON”“撤销最近一次导入”“下载旧版扫描记录”并列放置；空 `business-preview` 从一开始存在并有 padding/background。screenshots/backup-390.png 显示连续三个宽按钮，随后空深蓝色块、未满足条件的确认框和灰色合并按钮。首次用户尚未选文件，就需要理解历史格式、撤销与恢复确认。

**整改：** 按“保存一份备份”“从备份恢复”分组，主下载保持主级；撤销靠近最近导入结果；旧版记录收进“旧版记录”展开区。未选文件时隐藏空预检容器，确认选项和合并动作在预检通过后展示，保留无新增/格式错误的具体说明。减少首屏控制数量，不改备份契约与校验。建议 `$impeccable distill` / `onboard`。

**验收：** 空状态无空色块；先选文件再读预检与确认；失败/零新增时不会显示可提交假象；撤销仍可发现。

## Cognitive load / 情绪旅程

- 首页五个作品按钮 >4，但数量就是展览内容，且名称、序号和图像有意义，不应机械压成隐藏菜单。真正的负担在同一区同时提供图录、入场、三维、两箭头、五选择、继续浏览；按“选哪朵 / 进入 / 其他观看”分组即可。
- 详情默认展示方式是两按钮加“更多”，渐进披露合理；不必把所有三维选项直接铺开。
- 备份初始态同时出现下载、撤销、旧版、文件、确认、合并，超过首次操作所需，A5 是应优先削减的分支。
- 情绪高点是完整花卡在靛蓝光场中呈现；浅底原型说明使观看转向理解。低点是手机详情长滚动末尾“返回作品”比“留下记忆”更显眼，收藏却在页首；可在未来用同一收藏控件复用明确收尾，但本次不必增加新系统。
