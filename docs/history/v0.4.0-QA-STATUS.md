## Visual scope and known limitations

This is a synthetic, textured CGI hand. Anatomy/contact and motion are suitable for reviewing the new direction, but it does **not** establish a documentary-photography-quality hand. Source-scene geometry has positive clearance, not a measured zero-gap physical grasp. CSS screen registration is assessed separately. No generated hand image is passed off as an actual photographed person or filmed performance.

The supported cloud browser has WebGL disabled. Rendered fallbacks and UI behavior were checked, but live GPU hero/flower appearance, shader performance and MindAR matching remain unverified. All five physical cards still require individual iPhone/Android testing, including pose alignment, target loss/reacquisition, wrong-card rejection, collection gating, thermal behavior and repeated stop/start. Programmatic target binding is not proof of physical recognition.

Native wheel input was exercised forward and in reverse. All 32 hand assets loaded without HTTP/resource failure, and paired layers never disagreed. A fine-input replay recorded 1,227 painted samples with zero incomplete hand targets and exact initial-pose restoration. The earlier coarse replay recorded one transient incomplete IMG flag among 4,788 samples, without an observed visual blank. Median cloud rAF gap was 16.7ms, with a 150ms maximum movement interval; this is not a promise of device fluidity.

Short landscape (844×390) has no horizontal overflow, broken resources or overlapping navigation. The 660px minimum-height hero extends below that short viewport, so the hand begins below the first fold. Desktop and phone portrait are the primary reviewed presentations.

Public deployment and unauthenticated live checks are recorded in `DEPLOYMENT-v0.4.md`. Production zevth.work is outside this candidate; no source/backup/rollback acceptance for production has been executed.
