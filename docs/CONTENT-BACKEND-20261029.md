# 内容后台边界与建议（2026-10-29）

## 已确认

用户希望后台编辑作品、故事和音频，发布后网站更新。未要求访客账号、社交或花册跨设备同步。当前仍处于预览验收阶段，不部署正式服务器。

## 建议：增加内容管理与发布服务，前台继续静态交付

流程：管理员登录 → 编辑草稿 → 上传音频或图片 → 预览完整作品 → 发布 → 生成带版本号的内容清单 → 网站读取已发布版本。后台停机时，前台仍使用最近成功发布的内容。

最小范围：作品标题、中英文名、简述、故事、来源与署名、讲解文字、音频及合成标识、上架状态、排序。五款作品 key、targetIndex、识别模型/target 配对属于程序契约，不开放为随意编辑字段；新增第六款需要资源与识别流程另验。

内容与程序分开：将 cards.mjs、详情页中的原型介绍、设计标注、讲解文字统一抽取到同一内容模型；音频存在和 audioAvailable 从同一发布清单产生。仍保留随构建的内容作为首次加载/网络失败回退。不要只修改 cards.mjs 而遗漏详情页硬编码内容。

发布至少包括：草稿与已发布状态、作品页面预览、媒体有效性检查、引用完整性校验、发布时间与发布版本、上一版本回退。前台只读取已发布内容，不读取草稿或后台数据库。

## 部署建议与待核对项

优先单个轻量服务加 SQLite 与媒体目录，继续利用现有静态站点托管；具体运行时应先核对服务器现有服务、持久化磁盘、备份位置和反向代理，再决定。此处是项目范围建议，并非已实现后台或已验证的服务器方案。

后台需要管理员认证、服务端权限检查、上传类型/大小限制和受控存储路径；不能仅靠隐藏管理网址。上线前以真实环境验证登录、发布和回滚。若未来出现多人同时编辑或多实例部署，再评估更换数据库，当前不提前扩大。

## 本轮落地顺序

1. 先补齐本机花册与扫描记录、备份恢复，避免错误的数据语义进入未来服务。
2. 完成现有前台的视觉改版与互动验收。
3. 按确认后的前台内容结构实施管理后台和内容发布接口。
4. 预览环境验证“编辑 → 预览 → 发布 → 前台回读 → 回退”，再准备正式部署。

未执行：后端安装、管理员账号创建、数据库写入、生产发布。当前已有的前台本机数据仍在用户浏览器，不会上传到内容后台。
